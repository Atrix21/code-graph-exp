## 2. Why SignalStream is not the starting point

| Measured | SignalStream | DocuParse | nestjs-boilerplate (S) |
|---|---:|---:|---:|
| Language | Go (+ 983-line React dashboard) | Go | TypeScript |
| Non-test source lines | 2,612 | 10,445 | 6,268 |
| Non-test source tokens (ESTIMATE) | ≈ 17k | ≈ 76k | ≈ 44k |
| Packages | 16 | 25 | — |
| Top-level `func` declarations | 90 | 354 | 199 functions + methods |
| Interfaces | 5 | 27 | 4 |
| `go` statements / `make(chan …)` | 6 / 4 | 37 / 17 | — |
| Commits | **2** | 19 (1 is a fix) | 2,126 upstream (≈ 34 `fix` commits touching `src/`) |

**Assessment.**
- **It is smaller than the repository we already found too easy.**
  - SignalStream's whole backend is about 17k tokens, so an agent can read all of it in one sitting.
  - It is 0.4× the size of experiment 1's repository, where a grep-equipped agent already scored 100%.
- **It has no bug history.** With 2 commits, there are no historical bugs to mine.
- **The good part does not fix the size problem.** Its event pipeline (ingestion → enrichment → embedding → Qdrant → alerting → SSE) is exactly the kind of architecture the hypothesis is about, but at this size it cannot test scale.
- **DocuParse is the same story.** It is 1.7× the size of S, has 19 mostly feature commits, and is also Go.
- **The owner's direction rules both out.** Using either would also have meant building a Go extractor for small repositories, which the owner has ruled out: "move up in size, not down" (E3-D02).

### 3.3 Navigation difficulty: what an agent faces

| Measured | S | M | L |
|---|---:|---:|---:|
| **Callee name ambiguity**: declarations sharing a callee's simple name, mean / p90 | 6.9 / 15 | 4.6 / 7 | **214 / 318** |
| Share of internal call edges whose callee name is unique | 0.13 | 0.74 | 0.69 |
| 2-hop neighbourhood of a random function: files (p50 / p90) | 14 / 28 | 39 / 96 | 55 / 361 |
| 2-hop neighbourhood: communities (p50 / p90) | 4 / 5 | 5 / 7 | 5 / 17 |
| Execution reach from an HTTP handler: max depth (p50 / p90) | 5 / 5 | 5 / 9 | **21 / 26** |
| Execution reach from an HTTP handler: files reached (p50 / p90) | 13 / 21 | 9 / 17 | **473 / 999** |

**Observations** (new, measured):
- **Name lookup in Twenty is unusually ambiguous.** Callee names such as `execute`, `handle` and `run` are each shared by hundreds of command and job classes, so a name-based grep returns hundreds of candidates.
- **Twenty's execution closures are an order of magnitude deeper and wider.** From a handler they run about 21 calls deep and reach about 470 files.
- **Ambiguity is not monotone in size.** M is less ambiguous than S. S's CRUD modules repeat names like `findById`, `create` and `update` across modules.

These are the properties where structural navigation could plausibly beat text search. Whether it does is the experiment.

## 4. Other open-source candidates considered

Summarised from `notes/external-research.md` (sources cited there):
- **novu `apps/api`** (NestJS, ESTIMATE ≈ 162k lines) is the fallback middle-large point. It is weaker: only 13 merged issue-linked PRs since 2026-06-01, against 291 for Immich and 462 for Twenty.
- **Rejected:**
  - nestjs/nest: a framework library, not an application.
  - amplication: inactive since June.
  - outline, strapi, medusa, n8n: not NestJS, so they would add a framework confound; n8n is also source-available.
  - Go repositories: would need a new extractor and add a language confound.
- **No vetted instances exist.** None of the selected repositories appears in SWE-PolyBench, Multi-SWE-bench, SWE-bench Multilingual or SWE-bench Pro, so tasks must be mined and audited by us.
- **Licences.** Immich and Twenty are AGPL-3.0, and Twenty's `@license Enterprise` files are commercial. We only analyse local copies, and nothing is redistributed. Results report paths, not code.

## 5. Hyrra/TASC

It is a Python multi-service work project, so it would add a language and extractor confound. It also requires authorisation and care with sensitive data. The ladder above answers the scale question without it, so it is **not needed** for experiment 3. It could later serve as a private generalisation check (Python extractor needed), only if the owner authorises a local repository copy.
