# Experiment 3: decision log

Format: **ID** · decision · reason · alternatives rejected. Experiments 1 and 2 are immutable reference points; nothing here changes their data, configs or conclusions.

- **E3-D01** · Repository discovery (2026-11-09). SignalStream is not on this machine; it is the owner's public repo `Atrix21/signalstream` and was cloned read-only to `targets/exp3/signalstream` (@0edb295). There is no IntelliDoc locally or among the owner's 48 GitHub repos; the closest personal project is DocuParse (local, Go, cloned read-only to `targets/exp3/docuparse` @8c67a79). Hyrra/TASC copies exist under `~/dev/work/hyrra` and `~/obsidian/hyrra`; **only the directory names were listed, no file was opened** (work project, not authorised). · The brief said not to assume paths and not to touch work systems.
- **E3-D02** · SignalStream and DocuParse are not scale targets. Measured: SignalStream has 2,612 non-test Go lines (30 files) and 2 commits; DocuParse 10,445 lines (116 files) and 19 commits, almost all feature commits. The experiment-1 repository has 6,268 non-test TypeScript lines. SignalStream is 0.4× the size we already showed to be too easy, and neither has a bug history. · The owner's instruction (mid-session): "we need to move up in size not down, and not [build] architecture to support my repos". A Go extractor (planned for these repos) was dropped before any code was written; a SignalStream analysis agent was stopped.
- **E3-D03** · Hold language and framework constant; climb a ×10 size ladder of real TypeScript/NestJS backends: **S** = nestjs-boilerplate (6.3k non-test lines, experiment 1), **M** = Immich server (62.6k), **L** = Twenty server (763k). · The existing TypeScript-Compiler-API extractor, chunkers, retrieval methods, MCP server and agent harness work unchanged, so effort goes into tasks and measurement. Holding language and framework constant removes a confound that a Go or mixed-language ladder would add. · Rejected: Go repositories (would need a new extractor and add a language confound); one very large repository only (no scale gradient).
- **E3-D04** · Snapshots: sparse, depth-1 clones pinned by commit (`immich-app/immich` a203e288, `server/`; `twentyhq/twenty` bde4ff13, `packages/twenty-server/`) in `targets/exp3/` (git-ignored). Immich server dependencies installed with `pnpm install --ignore-scripts --filter ./server` (lifecycle scripts not run). Twenty dependencies not installed yet (12% of call sites unresolved without them).
- **E3-D05** · Scale fix to shared graph code: `graphHash` and `exportGraphJson` now stream element by element. Twenty's canonical graph JSON exceeds V8's maximum string length (`RangeError: Invalid string length`); extraction itself had finished (71 s, 4.4 GB). Output bytes are identical to the old implementations: a new test compares both on fixtures and re-derives the recorded experiment-1 base-graph hash. · Needed for any repository above ~5k files; changes no result of experiments 1–2.
- **E3-D06** · Complexity profile is computed from the graph by `scripts/exp3/graph_profile.py`: separate measured quantities, no composite score. Module boundaries are measured three ways (first directory, first two directories, Louvain communities on the file dependency graph). · Directory-based modules mean different things in feature-organised (nestjs-boilerplate) and layer-organised (Immich: controllers/, services/, repositories/) code; a community partition is architecture-agnostic. A single "complexity score" would hide which property matters.
- **E3-D07** · Compact agent-facing context prototype (`src/retrieval/compact-context.ts`) measured on experiment 1's frozen test runs (no model calls; `results/compact-prototype.json`). Pointer-style output (location, signature, nearest neighbours; no bodies) at ≤ 800 tokens kept 72% of relevant symbols vs 85% for hybrid's 6.3k-token native context. **At equal token cost, adding relationship lines did not beat listing more ranked symbols** (hybrid 0.70 with relations vs 0.72 without; similar for custom_graph; relations helped the weaker BM25/embeddings rankers at ~400 tokens). · Hence the protocol compares graph and no-graph compact tools at equal token budgets, never "graph tool vs baseline" alone.
- **E3-D08** · Ground truth is never produced by the retrieval systems under test. Sources: fix commits of merged PRs (functions changed), linked issue text as the query (verbatim), and, where feasible, executable oracles (type-checker errors after a signature change; failing tests after a change; runtime traces). Communities used as task-complexity covariates are computed from the import graph only (an extractor-independent relation). · Avoids circularity between our graph and the labels it is scored against.
- **E3-D09** · Delegation: an external-research agent (literature, benchmarks, candidate repositories) and an Immich repository-analysis/bug-mining agent (Sonnet), both writing to `notes/`. Methodology and retrieval-architecture work stayed with the lead (full context of experiments 1–2). No two agents implement the same component.
- **E3-D10** · Task selection is method-independent. Candidates are excluded only for title-only reports, reports stating the fix mechanism, symptoms caused outside the analysed code, or unresolvable ground truth; difficulty strata (easy/medium/hard) are computed from lexical overlap, fix span and boundary type only. A retriever's rank (the mining agent's BM25 screen, its A/B/C tiers) is never used to include, exclude or tier tasks. · Choosing tasks on which one method fails biases the comparison against that method.
- **E3-D11** · Historical bugs are not automatically hard (Immich mining, `notes/immich-analysis.md` §3): BM25 put the fixed file in the top 10 for 78/97 candidates, and the median fix touches 1 file. The benchmark keeps the realistic mix, oversamples the hard stratum (≥ 50% cross-module), and reports every result by stratum. Twenty's reports come more often from maintainers' PR text (11/28 sampled server fixes link an issue), so its tasks need a leakage audit; a report is dropped, not rewritten, when no symptom-only text exists.
