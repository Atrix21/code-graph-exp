# Decision log

Format: ID · date · decision · why · alternatives considered.

- **D-001** · 2026-11-08 · Empty working dir → build a fresh project; use a real open-source TS backend rather than a synthetic fixture. · A third-party codebase avoids designing code structure that favours our graph. · Synthetic fixture (rejected: designer bias).
- **D-002** · TypeScript Compiler API pinned to **typescript@5.9.3** (latest 5.x). · npm `latest` is 7.0.x (native Go port, different API surface); 5.9.3 is the stable JS Compiler API and matches the target repo's own TS version. · 6.0.x.
- **D-003** · Target = `brocoders/nestjs-boilerplate@9620f159`. · Ranked 1st of 10 measured candidates (Haiku recon): MIT, active, 170 non-test-free TS files, controller→service→repository + DI, abstract repos with 2 implementations, OAuth/S3/mail integrations, tests; type-checks cleanly. · pingvin-share (archived, no tests), growchief (AGPL, no tests), domain-driven-hexagon (thin domain), realworld apps (no licence/too small).
- **D-004** · Ground truth via **injected bugs** in a single benchmark revision. · All methods see one revision; labels are verifiable by construction (root cause = mutated function); enables a later downstream "identify the root cause" experiment. · Historical bug-fix commits (would need many revisions); hypothetical bugs on correct code (less realistic).
- **D-005** · Snapshot keeps only `src/`, `test/`, `package.json`, tsconfigs, `nest-cli.json`, `LICENSE`, `.gitignore`. · Equal source availability: Graphify/CRG would otherwise index docs/JS config files that other methods never see, and Graphify's doc path needs an LLM. · Index full repo (rejected).
- **D-006** · Target deps installed in `targets/deps`, symlinked as `targets/node_modules`. · TS type checker resolves `@nestjs/*`, `typeorm`, … by walking up parent dirs, while indexers crawling the snapshot never see node_modules. Upstream lockfile was out of sync (`npm ci` refused), so `npm install --ignore-scripts` was used; only type declarations matter.
- **D-007** · Proxy tokenizer `o200k_base`. · No Anthropic API key; counts are applied uniformly to every method's output. · chars/4 (cruder).
- **D-008** · Embedding model `Qwen/Qwen3-Embedding-0.6B` @ `97b0c614`, fp16 CUDA, last-token pooling. · Strong open code/text embedding model available locally; fits a 6 GB GPU. **Bug found and fixed**: the pre-existing HF cache lacked the sentence-transformers config, which silently fell back to mean pooling (smoke-test embeddings recall 0.0). Fixed by completing the snapshot, pinning the revision and making `embed.py` abort unless pooling is `lasttoken`.
- **D-009** · ripgrep binary pinned via `@vscode/ripgrep@1.18.0` (rg 15.0.0). · `rg` on this machine is a shell function wrapping Claude Code, not a reproducible binary.
- **D-010** · Graphify run with `--budget 8000` (shared budget) as primary; its default 2000 reported as a secondary variant. · Same budget for every method. Graphify's budget is ≈3 chars/token and can overflow, so measured tokens are reported as-is.
- **D-011** · CRG run on a clone at the neutral path `/tmp/cgbench/w`. · CRG FTS-indexes absolute paths; words in the real checkout path (`code`, `graphs`, `experiments`) would match bug-report words.
- **D-012** · CRG primary policy `search_expand` (search → callers_of/callees_of of top-2 callable hits). · Mirrors CRG's own `debug_issue` prompt and `debug-issue` skill; no single NL→context tool exists. Search-only and embeddings variants reported separately.
- **D-013** · Graphify auto-refresh side effect: the first run of the pinned Graphify CLI auto-updated the user's global `~/.claude/skills/graphify` (0.9.63 → 0.9.104). Restored byte-for-byte from the installed 0.9.63 package (SKILL.md + references), backup of the 0.9.104 copy kept in the session scratchpad; adapters now set `GRAPHIFY_NO_AUTO_REFRESH=1`. CRG adapter sets `CRG_HOME`/`CRG_DATA_DIR` inside the output dir.
- **D-014** · Split: seeded (20261108) stratified by lexical overlap, 2 per stratum → 6 dev / 14 test, assigned before any comparative run.
- **D-015** · Uniform rendering for token-efficiency comparisons (symbol span ≤ 80 lines) in addition to native output tokens. · Separates ranking quality from output formatting; native tokens still reported.
- **D-016** · Metrics evaluate exactly what is in each method's native context (results beyond the method's token budget are not counted). · An agent only sees what is returned.
